# Home Page Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the Home page's contradictory counts, its missing verdict on phones and its weak hierarchy, without changing routes or other pages.

**Architecture:** One backend field and one spotlight fix in `api/views/home.py`; frontend changes in `HomePage.tsx`, the home feature components and one base-theme line. Visual verification uses the rebuilt `suspicious_ui` image and `scripts/theme-sheets.mjs`.

**Tech Stack:** Django REST (backend), React 19, MUI 9.4, Recharts 3.10, Vitest 4 browser mode, Playwright.

**Spec:** the approved chat design of 2026-10-09 (audit findings H1 to H5, "per-user counts, go with the UI plan") plus `docs/specs/2026-10-08-ui-theme-foundation-design.md` for theme rules. No separate spec file: bounded change to an existing page.

## Global Constraints

- No route change, no change to any page other than Home, no new dependency.
- Every theme keeps its contrast floor (`contrast.test.ts` stays green); no hardcoded colours, use theme tokens.
- Every design decision has a one-line reason (anti-slop C-1); UI strings plain, no filler; no fabricated numbers.
- Backend: Django tests live in `Suspicious/Suspicious/api/tests/`; run with `python manage.py test api.tests.<module>` from `Suspicious/Suspicious`, or in the container: `docker compose --env-file .env run --rm --no-deps suspicious python manage.py test api.tests.test_home_summary`.
- Frontend toolchain: Node 22 (`export PATH=$CLAUDE_JOB_DIR/tmp/node-v22.13.1-linux-x64/bin:$PATH`), `npx pnpm@11.1.3`, `npx vitest run`, `npx tsc -b`, `npx eslint .` (0 errors required, 4 existing warnings are fine).
- Visual check: `(cd deployment && docker compose --env-file .env build suspicious_ui && docker compose --env-file .env up -d suspicious_ui)`, then `UI_USER=elena.voss@meridian.example UI_PASS='MeridianDev!2026' CHROMIUM_PATH=$(ls ~/.cache/ms-playwright/chromium_headless_shell-1234/*/chrome-headless-shell) node scripts/theme-sheets.mjs <outDir>` from `suspicious-ui/`. Baseline captures of Home: `$CLAUDE_JOB_DIR/tmp/audit-home` (light and midnight, 1440 and 390 wide).
- Never stage anything under `deployment/` (an unrelated uncommitted `compose_apps.yaml` edit lives there).

## Review Focus

- A CISO: the share card stays scope-based and the spotlight stays the scope total. Pinned in Task 1.

### Task 4: Hierarchy, empty donut and share card

**Files:**
- Modify: `suspicious-ui/src/pages/HomePage.tsx`, `suspicious-ui/src/features/home/api.ts`, `suspicious-ui/src/pages/__tests__/HomePage.test.tsx`

**Interfaces:**

Design (each with its reason):
1. Welcome heading: `variant="h2"` (22px) instead of the small bold line. Reason: the page title carried less weight than card titles.
2. Share card: `myCount = home?.monthly?.user_items ?? donutTotal` for non-CISO users (reason: the count is the user's submissions, not the sum of verdict buckets that exclude unfinished cases). Show the number large (`variant="h3"`) with "of {orgCount} org submissions this month" beside it, then the progress bar and the existing percentage line. CISO keeps scope wording and `scopeCount`.
3. Spotlight: drop the small "Spotlight" label and the repeated heading when the card already shows the number; keep `spotlight.description` and its CTA as the single primary action of the page (server decides its label: "Submit an item", "Open dashboard", "Open investigation"). Reason: the heading repeated what the card said and the CTA was duplicated three times.
4. Threat distribution: remove the extra "Submit" button from this card. When all four counts are 0, do not render the 220px chart box or the four zero legend rows; render `EmptyState` (existing component) compactly (`minHeight: 120`). With data, the donut and legend are unchanged. Reason: four zero rows and a 220px empty box say the same thing as one line.
