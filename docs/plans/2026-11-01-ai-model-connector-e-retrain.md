# AI Model Connector, Plan E: Retrain, Gate and Registry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `manage.py ai_model_retrain` (and the Celery start/poll tasks behind it) turns the label ledger into a gated candidate model version, stored as a bundle in object storage and registered in the database, without ever touching the active model unless a human promotes it later (Plan F).

**Architecture:** A pure-Python training package (`Analyzers/AIMailAnalyzer/training/`) holds the recipe, the groups, the gate and the bundle format; it has no Django and no network. The inference server wraps it in a single-job `/v2/train` API and loads bundles through `/v2/reload`. Django owns the registry (`ModelVersion`, `ModelEvent`), exports the ledger, hands the server presigned URLs and polls with short Celery tasks. Plan E ends at a `candidate` version; shadow and promotion are Plan F.

**Tech Stack:** PyTorch (existing `ResNetMLP`), scikit-learn (`StratifiedGroupKFold`), NumPy, FastAPI, Django, Celery, the project's `ObjectStore` layer.

**Spec:** `docs/specs/2026-10-30-ai-model-connector-design.md` sections 2 (one text function, resources), 3 (registry, bundle), 5 (recipe, groups, gate), 9 (tiers), Evidence. Master plan: `docs/plans/2026-10-30-ai-model-connector.md`, Plan E. Earlier plans are merged in the local `design/ai-model-connector` branch.

## Guidance used

Official documentation read for this plan (links checked on 2026-11-01). Where a page did not answer the question, it is said.

- scikit-learn, [cross-validation iterators for grouped data](https://scikit-learn.org/stable/modules/cross_validation.html): samples that are not independent need a `groups` argument so that "all the samples in the validation fold come from groups that are not represented at all in the paired training fold". `StratifiedGroupKFold` keeps class proportions where the group constraint allows and can produce imbalanced splits; the guide documents repeated variants only for non-grouped splitters, so repeats here loop over seeds with `shuffle=True` ([API](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.StratifiedGroupKFold.html)).
- scikit-learn, [probability calibration](https://scikit-learn.org/stable/modules/calibration.html): the calibrator should be fit "on a dataset independent of the training data"; temperature scaling has one parameter `T` learned by minimising log loss on a hold-out set and "does not alter the accuracy"; isotonic regression overfits below about 1000 samples; Brier score and log loss are of "limited use for assessing calibration alone", so a reliability curve and a binned error are needed. The page has no ECE function; the binned error is written in the plan.
- Guo et al., [On Calibration of Modern Neural Networks](https://arxiv.org/abs/1706.04599): temperature scaling, a single-parameter variant of Platt scaling, is "surprisingly effective". (The abstract page does not define the binning; the 15-bin equal-width form is the common convention and is stated as this plan's call.)
- PyTorch, [`torch.load`](https://docs.pytorch.org/docs/2.15/generated/torch.load.html): `weights_only=True` restricts the unpickler to tensors, primitives and dictionaries, and the page says "Never load data from an untrusted source". Bundles hold state dicts only, are loaded with `weights_only=True` (as `inference_server/server.py` already does), and are checked against a SHA-256 manifest first; `np.load(..., allow_pickle=False)` for arrays.
- Celery, [Redis broker notes](https://docs.celeryq.dev/en/main/getting-started/backends-and-brokers/redis.html): the default visibility timeout is one hour and a task that outlives it "will be executed again, and again in a loop"; raising it is "not recommended". This is why training runs in the server and Celery only starts and polls with short tasks, as the spec says.
- Amazon S3, [presigned URLs](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html): a URL works until it expires and "you can use the presigned URL multiple times"; an upload to an existing key replaces the object; Signature V4 supports checksums. So URLs are short-lived, one key per job and version, and the SHA-256 is verified on our side. (The page was thinner on how a checksum is enforced in the signed request; the plan does not rely on it. RustFS compatibility is checked in Task 6.)
- MLflow, [model registry workflow](https://mlflow.org/docs/latest/ml/model-registry/workflow/): a named alias (such as `champion`) is a mutable pointer to a version, serving code follows the pointer, tags annotate validation status. The page does not document rollback; moving the pointer back is the obvious reading and is how `active` and `previous` work here.
- statsmodels, [`proportion_confint`](https://www.statsmodels.org/stable/generated/statsmodels.stats.proportion.proportion_confint.html): the Wilson interval is contained in [0, 1]; Clopper-Pearson (`beta`) is conservative. The report uses Wilson, written out by hand (about ten lines) and tested against reference values, so the inference image gains no dependency.
- Breck et al., [The ML Test Score](https://research.google/pubs/the-ml-test-score-a-rubric-for-ml-production-readiness-and-technical-debt-reduction/): 28 tests across data, model, infrastructure and monitoring, with reproducibility of training among them. The abstract page does not list the tests and the PDF could not be read as text, so only the headline is used: the plan adds a reproducibility test (same ledger digest and seed give the same metrics).
- sentence-transformers [efficiency page](https://www.sbert.net/docs/sentence_transformer/usage/efficiency.html): nothing found about chunking long texts; the chunk size is therefore checked against the tokenizer in Task 2 instead of taken from documentation.

## Review Focus

- A bundle with a changed byte, an extra file, a path in a name, a pickle in `knn_index.npz`, or a manifest hash mismatch is refused before anything is loaded (Task 4).
- A second `POST /v2/train` while a job runs gets 409; a cancelled job leaves no bundle and no `candidate` row; the server restarting mid-job leaves the registry row in `failed` after the next poll (Task 6, 8).
- Near-duplicates and campaign members never straddle a train/test fold or a calibration split (Task 2, 3).
- A head with fewer than 8 samples in any class fails the whole candidate, with the head and class named (Task 3).
- The gate compares against the active recipe retrained on the same folds, not against the active weights (Task 3).
- Presigned URLs: expire in minutes, one key per job, the server accepts only configured hosts and caps downloads (Task 6).
- Classify keeps answering during training (thread and slot limits) (Task 6).
- Version 0 keeps the legacy decision rule bit for bit unless a calibration is attached by the explicit fit command (Task 9).

## Calls made in this plan

- **Ruling E1: go/no-go checkpoint after Task 5.** Tasks 1 to 5 are the offline recipe and gate. They must reproduce the evidence in the spec (grouped accuracy about 0.85, Dangerous called Safe about 5% or lower, within seed noise) on the real dataset before Tasks 6 to 9 start. If they do not, the plan stops and the spec is revisited. Cost if wrong: Tasks 6 to 9 are built on a recipe that does not hold.
- **Ruling E2: the dataset fixture stays out of git.** The 505-mail dataset (`dataset.pkl` in the ai-analyzer-wip worktree) holds embeddings derived from real mails. A script (Task 5) converts it to an `.npz` (no pickle) outside the repo; the slow regression test reads its path from `AI_EVAL_DATASET` and skips when unset.
- **Ruling E3: canonical text form.** The live path classifies the parsed `.txt` body. The ledger embeds `text_from_message` (plain part, else reduced HTML). Task 1 measures the gap on cases that have both; the rule is: if the median cosine similarity is 0.98 or more, the forms are treated as equivalent and the recipe's preprocessing version records `body-v1`; if lower, `text_from_message` is changed until it is, because the model must be trained on what classify will see. The decision and the figures go into `docs/components/analyzers.md`.
- **Ruling E4: Wilson by hand, no statsmodels.** One less dependency in the image; tested against known values.
- **Ruling E5: temperature fit directly on logits** (a one-parameter minimisation of negative log-likelihood), not through `CalibratedClassifierCV`, because the heads are PyTorch modules and the spec calls for one temperature fitted on grouped held-out predictions.
- **Ruling E6: binned calibration error.** 15 equal-width bins on the top-class probability, weighted by bin count; the gate threshold 0.12 is the spec's.
- **Ruling E7: repeats.** 3 repeats of 5-fold `StratifiedGroupKFold(shuffle=True, random_state=seed)` with seeds 0, 1, 2 (the spec's default); metrics are computed per repeat then averaged; the report keeps the counts pooled over the repeats (each mail counted once per repeat, `pooled_repeats` and a `note` say so), and Wilson intervals use the per-repeat mean counts (pooled count divided by the number of repeats), so repeating does not narrow them.
- **Ruling E8: heads and weights format.** state dicts stored as `heads/<head>.npz` (Ruling E15 replaced the spec's `.pth`), plus a SHA-256 per file in the manifest. Cost if wrong: a loader bug; a format change needs a bundle version bump.
- **Ruling E9: server fetches only configured hosts.** `AI_BUNDLE_HOSTS` (comma separated `host:port` allow-list, default the object store host from the connector config) restricts presigned URLs the server will GET or PUT, scheme http or https, no redirects followed, download cap 200 MB.
- **Ruling E10: scheduling.** The monthly retrain is a `Schedule` that is a no-op unless `retrain_enabled` is true (default false). Plan G adds the UI.
- **Ruling E11: chunking is token-based.** The spec's 90 words (at most 8 chunks) is the starting point; Task 2 measures how often a 90-word chunk exceeds the encoder's 128-token window on the dataset and, if more than 5%, switches to chunks sized by the tokenizer. Measured in Task 2 on the 505-mail dataset: 77% of 90-word chunks exceed 128 tokens. Because the spec's evidence was measured on 90-word chunks, Task 5 runs both chunk forms on the real dataset and picks one; the preprocessing version string records the chunking (`chunkmean-words90-v1` or `chunkmean-tokens-v1`, the constants `PREPROCESSING_VERSION_WORDS90` and `PREPROCESSING_VERSION_TOKENS` in `training/recipe.py`). Writing it into the manifest is Task 4's concern.
- **Ruling E12: one temperature per component.** A deviation from the spec's single temperature, so that calibration matches the recipe the spec's evidence was measured with (`exp_e_combined.py`): the head hierarchy and the 5-NN vote are each smoothed (`(1 - 0.05) * P + 0.05 / 3`), each calibrated by its own temperature fitted on grouped held-out predictions (bounds 0.2 to 30), and the main decision is the mean of the two calibrated components. Calibration therefore stores `temperature` as `{"hierarchy": float, "knn": float}`. Cost if wrong: one more fitted parameter; the gate's calibration check still judges the blend.
- **Ruling E13: check 5 is measured cross-half.** The stored `tier_cutoffs` are chosen on all held-out predictions, but check 5 is not judged on the predictions that chose them: on the calibration group halves of each seed, the High cutoff is chosen on half A's calibrated predictions and High rows and correct High rows are counted on half B, then the reverse; counts are pooled over halves and seeds, and the value is the pooled cross-half High precision (threshold 0.90). The check also fails when a half has no cutoff reaching 0.90, or when the evaluated High count is below 5% of all rows (floor). The report gives the High count, the precision and the Wilson lower bound (informational, not the pass rule). Cost if wrong: a stricter check 5 than the spec's wording; a candidate with a tiny, lucky High tier no longer passes.
- **Ruling E14: the manifest hash is pinned outside the bundle.** The manifest holds the hashes of every other file, so it is the root of trust and a bundle fetched from storage cannot vouch for itself. The trainer returns the SHA-256 of `manifest.json` in its job report, Django stores it in `ModelVersion.manifest_sha256` and passes it with each `bundle_url` to `/v2/reload`; `read_bundle` requires it and compares it (constant time) before parsing the manifest. Version 0's import records the hash it computed. Cost if wrong: one more field to carry; a bundle swapped in storage is refused.
- **Ruling E15: heads are `.npz`, not `.pth`, and `torch.load` is not used on bundle bytes.** Python's `zipfile` and torch's zip reader read the central directory differently, so a size check done with `zipfile` can be bypassed by an archive torch reads another way (reviewed: a ~1 MB `.pth` inflated ~1 GB). A head is one float32 array per state-dict key, written with `np.savez` (uncompressed) and read with `np.load(allow_pickle=False)` after checks done with the same Python zip reader that `np.load` uses: stored members only, at most 64, total size bounded, every array header consistent with its member size, key set and shapes equal to a fresh `ResNetMLP(input_dim, NUM_OUT[head])`, finite values; tensors come from `torch.from_numpy(arr.copy())` into `load_state_dict(strict=True)`. The spec's bundle table (`heads/*.pth`) is superseded by `heads/*.npz`. Cost if wrong: a conversion step for the trusted legacy files (Task 7).
- **Ruling E16: token chunks by default.** Decided at the Task 5 checkpoint: on the 505-mail dataset `chunkmean-tokens-v1` and `chunkmean-words90-v1` are within noise on the main metrics (accuracy 0.854 against 0.861, Dangerous called Safe 4.7% against 3.9%), all six checks pass for both, and token chunks halve Dangerous called Safe on held-out campaigns (6.5% against 12.6%) without the silent truncation of 77% of 90-word chunks. `chunk_mean_embedding` defaults to `by_tokens=True` and `PREPROCESSING_VERSION` is `PREPROCESSING_VERSION_TOKENS`; words90 stays supported. Version 0 keeps `legacy-first128`. The slow regression test evaluates the token embeddings by default. Cost if wrong: one re-embedding of the ledger.
- **Ruling E17: the High cutoff.** With the blend, every row at 0.60 or above was already 91% right, so the old rule (smallest cutoff from 0.60 reaching 0.90) put High at the Medium boundary and left Medium empty. The stored High cutoff is now `max(0.85, t)`, where `t` is the smallest probability whose rows at or above it reach 0.95 precision (`HIGH_CUTOFF_FLOOR`, `HIGH_CUTOFF_PRECISION`); Medium stays at 0.60. Check 5 keeps its 0.90 threshold and the 5% floor of Ruling E13 and chooses the cutoff on each calibration half by the same rule, so it judges the rule that is stored; its detail says when the 0.85 floor decided. No cutoff reaching 0.95 means High is unreachable (check 5 fails). Cost if wrong: a smaller High tier than before.
- **Ruling E18: groups live in the campaign embedding space.** Near-duplicate groups and campaign groups are computed on each row's first-128-token campaign embedding (`cmp-e1`), as in the test bed and spec E8, not on the chunk-mean embedding the heads train on (at 0.95 chunk-mean gives fewer groups: 237 with tokens against 263). The Task 8 export supplies both vectors per ledger row. Cost if wrong: one more 768-float vector per row in the export.

## Contracts

- `training/groups.py`: `near_duplicate_groups(embeddings: np.ndarray, threshold: float = 0.95) -> np.ndarray` (component id per row, cosine similarity), `campaign_groups(campaign_embeddings, distance_threshold: float, ties: list[tuple[int, int]]) -> np.ndarray`.
- `training/recipe.py`: `HEADS`, `head_target(head, folder) -> int | None` (as in the test bed `lib_spike.py`), `chunk_mean_embedding(vectorizer, text, *, words=90, max_chunks=8, by_tokens=True) -> np.ndarray` (tokens by default, Ruling E16), `PREPROCESSING_VERSION_WORDS90`, `PREPROCESSING_VERSION_TOKENS`, `PREPROCESSING_VERSION` (equal to `PREPROCESSING_VERSION_TOKENS`), `fit_heads(X, folders, *, seed, epochs=30, threads=2) -> Heads` (with `input_dim`), `predict(heads, knn, X, *, temperature={"hierarchy": T, "knn": T}) -> Predictions` (mean of the smoothed, per-component calibrated hierarchy and 5-NN vote, plus sub-type probabilities and the per-component logits), `fit_temperature(logits, labels) -> float`, `fit_temperatures(predictions, labels) -> {"hierarchy": T, "knn": T}` (Ruling E12), `temperature_at_bound(T) -> bool`.
- `training/gate.py`: `run_gate(X, folders, groups_dup, groups_campaign, *, baseline_recipe, recipe=candidate_recipe, repeats=3, seed0=0) -> GateReport`; `X` is the chunk-mean embedding, while `groups_dup` (`near_duplicate_groups`, 0.95) and `groups_campaign` (`campaign_groups`) are computed on each row's `campaign_embedding` (first 128 tokens), not on `X` (Ruling E18); a recipe is `recipe(X, folders, train_idx, test_idx, *, seed) -> {component: logits}` (`(len(test_idx), 3)` logits per component; the gate calibrates each component and averages them; a recipe may add `resampling_skipped: [head, ...]`, collected as `GateReport.legacy_resampling_skipped`); `candidate_recipe` (the retrain recipe, components `hierarchy` and `knn`) and `legacy_recipe` (version 0: SMOTE + random oversampling then class weights, `hierarchy` only, needs imbalanced-learn, imported inside the function) are the two recipes, and `baseline_recipe` is the active version's (`legacy_recipe` for version 0); `GateReport.checks` is a dict of six named checks, each `{"passed": bool, "value": ..., "threshold": ..., "detail": str}`; `GateReport.eligible` is true only if all six pass; `GateReport.temperatures` lists the fitted `{component: T}` per seed and calibration half; `GateReport.tier_cutoffs["high"]` follows Ruling E17; `wilson(successes: int, n: int, z: float = 1.96) -> tuple[float, float]`; `ece(probs, labels, bins=15) -> float`.
- `training/bundle.py`: `write_bundle(dir, *, heads, calibration, knn, campaign_profile, manifest) -> str` (returns the SHA-256 hex of `manifest.json`), `read_bundle(dir, *, manifest_sha256: str) -> Bundle` (the hash is required, no default, 64 lowercase hex characters, and is checked against the manifest bytes before anything is parsed, Ruling E14; verifies every hash, refuses unknown or missing files, refuses names that are not plain file names), `BUNDLE_FILES`.
- Bundle layout (spec section 3): `heads/<head>.npz` (five; one float32 array per state-dict key, Ruling E15), `calibration.json` (`temperature` as `{"hierarchy": float, "knn": float}` (Ruling E12), `tier_cutoffs`, `held_out_groups`), `knn_index.npz` (`embeddings`, `label_ids`, `case_ids`), `campaign_profile.json`, `manifest.json` (version id, recipe id, preprocessing version, encoder id and hash, ledger snapshot digest, campaign refs digest, metrics and gate results, parent version, trainer revision, file hashes).
- Server: `POST /v2/train` body `{"job_id": str, "dataset_url": str, "bundle_url": str, "params": {...}}` returns 202 or 409; `GET /v2/train/{job_id}` returns (the report carries `manifest_sha256`) `{"state": "queued|running|succeeded|failed|cancelled", "progress": float, "report": {...} | null, "error": str | null}`; `POST /v2/train/{job_id}/cancel`; `POST /v2/reload` body `{"active": {"version_id": str, "bundle_url": str, "manifest_sha256": str} | null, "shadow": {...} | null}`.
- `ai_model.models.ModelVersion`: `version_id` (unique), `status` (`candidate|shadow|active|previous|discarded|failed`), `bundle_prefix`, `manifest` (JSON), `manifest_sha256`, `campaign_profile` (JSON), `parent` (FK self, null), `trigger` (`manual|schedule|import`), `triggered_by` (FK user, null), `created_at`, `job_id`. `ai_model.models.ModelEvent`: `version` (FK), `action`, `user` (FK, null), `at`, `note`. Status changes only through `ai_model/registry.py` functions, each writing a `ModelEvent`.

### Task 3: The gate

**Files:** Create `training/gate.py`, `tests/test_training_gate.py`.

- [ ] **1. Tests first:** `wilson(0, 10)` and `wilson(10, 10)` are inside [0, 1] and match reference values (computed by hand from the Wilson formula in the test); `ece` is 0 for perfectly calibrated synthetic predictions and the expected value for a hand-built over-confident set; the six checks: (1) Dangerous called Safe not above the baseline's rate plus 0.01 on the same folds, (2) macro-F1 not more than 0.02 below the baseline, (3) calibration error below 0.12, (4) every head has at least 8 samples in every class, else the check fails and names the head and class, (5) High-tier precision at least 0.90, (6) on folds split on campaign groups, Dangerous called Safe not above the baseline's rate plus 0.01; folds never separate a near-duplicate group (assert for every fold); calibration is fit only on predictions for groups outside training; the baseline is the active recipe retrained on the same folds (a test with a stub baseline records that it was called with the same train indices); `GateReport.eligible` is false if any check fails; the report holds per-class results with Wilson intervals, the confusion matrix, the tier table and the campaign-held-out result; a run is reproducible: same data and seeds give identical metrics.
